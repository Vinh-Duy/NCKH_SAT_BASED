# Multi-family pilot: witness validation and theoretical comparisons

Source: [raw CSV](../../runs/general_pilot_v1.csv) and [configuration/column guide](../../runs/general_pilot_v1.README.md). Analysis is generated by `scripts/audit_general_pilot.py`. Input CSV, metadata, statuses, and witnesses remain unchanged. `sources.json` records input and audit-source hashes; audit code need not match the historical solver source.

## Files

- `observations.csv`: 234 observations with validated labels and reference bounds/formulas.
- `summary.csv`: twelve family–h,k groups, not twelve instances or solver runs.
- `summary.tex`: coverage table; its exact-reference column counts instances with applicable exact formulas, not solver-proven optima. The English manuscript uses a translated presentation copy of this historical table.
- `sources.json`: data and audit scope, not an UNSAT certificate.

## Additional observations.csv columns

Graph, Instance, Family, h,k, Method, Repeat, V,E, Status, Span, and Wall_Time retain their input meanings. Status is unchanged.

| Column | Meaning |
|---|---|
| Recorded_LB | Final lower bound recorded by the solver pipeline, not the initial theoretical bound |
| Witness_Span | max−min recomputed from saved labels |
| Degree_LB | h+(Δ−1)min(h,k) if an edge exists, otherwise 0 |
| Theory_LB, Theory_UB | Applicable mathematical bounds, independent of final solver bounds |
| Exact_Reference | Applicable known exact formula; blank means no formula applied, not zero |
| Reference | Degree/equally-spaced-label bound, h=k tree formula, or L(2,1) grid formula |
| Excess_Over_Theory_LB | Witness_Span−Theory_LB; positive means this bound does not certify optimality, not that the bound is false |
| Theory_Optimal | True if a valid witness attains Theory_LB; does not overwrite original Status |
| Reference_Check | MATCH: attains the exact reference; ABOVE_EXACT: exceeds a known optimum; NA: no applicable exact formula |
| Within_Budget | Wall_Time ≤ Limit, recorded separately for budget-consistent coverage/timing |

The general upper bound assigns labels spaced by max(h,k), giving span ≤(n−1)max(h,k). It is elementary and potentially loose, **not the measured greedy upper bound**. Trees with h=k use exact=hΔ; L(2,1) grids with both dimensions ≥4 use exact=6. Proofs are in the [appendix](../../../paper/sections/theoretical_baselines.tex). No general formula is assumed for ER, BA, or L(3,2) trees.

## summary.csv columns

Family,h,k identify groups; Cases counts instances; Joint_OPT_Within_Budget counts instances jointly OPT within budget; Exact_Reference_Cases counts those with applicable formulas. For cadical/gurobi prefixes:

- `_OPT`, `_FEASIBLE`: observations by original status.
- `_Theory_Optimal`: witnesses attaining the mathematical lower bound.
- `_Paired_Median_Seconds`: median seconds on the jointly OPT-within-budget subset; read with coverage rather than ignoring unresolved instances.

This differs from Base/Sym summary schemas. The 61 bound-attaining instances already include the twelve exact-reference instances; do not add them. One run per backend does not assess repeated-run stability.

## Validation scope

Checks cover the complete 39-graph × three-pair × two-backend domain, duplicates/missing rows, seeded graph equality, independent BFS feasibility, configuration, statuses/bounds, witness timing consistency, applicable formulas/bounds, and paired-backend consistency. They do not remeasure time, recount CNFs, or verify UNSAT/ILP proof certificates. Valid labels alone do not make a FEASIBLE observation optimal.
