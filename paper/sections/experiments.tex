\section{Experimental design and available results}
\subsection{Scope of the results audit}
The audit dated September 28, 2026 revalidated witnesses from five current
runs: the multi-family pilot, the tree screen, the repeated tree comparison,
and the two main\_r1 symmetry runs. It used shortest-path distances and
cross-checked configurations, labels, statuses, and bounds across configurations
or backends. Other archived CSVs were inventoried by source, row count, and
hash, rather than implicitly certified as correct. The historical main\_r1
source differs from the current implementation; the audit therefore neither
recounts historical CNFs nor changes manifest hashes to bypass provenance
checks. Witness validation is not independent verification of an UNSAT certificate.
Detailed results are stored in \path{results/analysis/exact_review_20260928/}.

\subsection{Separation of datasets}
The tree comparison uses \path{results/runs/tree_l32_screen_v2.csv}:
\TreeGraphCount{} trees and \TreeObservationCount{} solver observations,
all with $(h,k)=(3,2)$. The smaller \path{tree_l32_compare_r1.csv} contains
three trees with 20, 30, and 40 vertices, each run three times per backend
to check the pipeline. The two main\_r1 runs concern $L(2,1)$ and compare
Baseline/Symmetry using Glucose; they are reported separately in
Appendix~\ref{sec:legacy-experiments}. Runs with different backends, budgets,
and source versions are not pooled as homogeneous measurements.

\subsection{SAT--ILP protocol}
CaDiCaL uses order encoding and span search with a fresh solver for each
trial. Gurobi uses assignment ILP with one thread, a greedy upper bound,
and a greedy MIP start. Both receive the same graph and $(h,k)$; symmetry
breaking is disabled in this comparison. Each backend runs sequentially
in a fresh process, with backend order rotated across instances and
repetitions. A preflight check verifies backend availability before the sweep.

Each tree-screen run has a 60-second external limit. \texttt{Wall\_Time}
includes startup, model construction, solving, and process cleanup; labeling
validation in the parent process is excluded. On external timeout, the run
retains the received greedy labeling, if available, and reports \FEAS.
This need not be the best incumbent found internally before interruption.
Only \OPT{} within budget counts as solved. An unavailable backend is
neither a timeout nor a win for another backend.

Peak RSS is the worker's operating-system-reported maximum resident memory,
including Python and native libraries; it is left blank if the process is
terminated before reporting it. SAT clause counts refer to the last model
returning a solution, while ILP constraint counts refer to the model built
at the greedy upper bound. These may use different spans, so their ratio
does not measure encoding savings at a common span.

For $L(3,2)$, the degree bound is $3+2(\Delta-1)=2\Delta+1$.
It is attained by \TreeTightCount{} of \TreeGraphCount{} trees: the feasible
labeling and mathematical bound together establish optimality. The other
two cases are \texttt{tree\_100\_seed5}, with $\Delta=4$ and span 10 rather

instances, but no UNSAT certificates were saved for independent verification
of all infeasibility conclusions. The data do not support the formula
$\lambda_{3,2}(T)=2\Delta+1$ for every tree.

input and audit-source hashes are stored in
\path{paper/generated/tree_screen_sources.json}. Revalidating labelings
does not reproduce runtime measurements or recount historical CNFs.

excluding preflight and work outside the measured runs. This is an exploratory
study, not evidence of large-scale performance.
All 234 rows and witnesses were checked: graphs were regenerated from their
configurations, vertex and edge sets were compared, label constraints were
checked using shortest-path distances independently of the encoder, and
CSV--witness consistency was verified. The audit does not reproduce timings,
CNFs, or UNSAT certificates.

CaDiCaL establishes optimality on 79/117 instances and Gurobi on 97/117.
Both report \OPT{} with the same value on 78 instances; 19 are \OPT{} only

\paragraph{Theoretical references.}
The nine $(h,k)=(1,1)$ trees use Proposition~\ref{prop:equal-tree}; the three
$(h,k)=(2,1)$ grids use Proposition~\ref{prop:grid}. All 24 backend results
on these 12 instances agree with the exact values. Across the pilot,
122 witnesses (61 instances, two backends each) attain the applicable
mathematical lower bound. Their labelings and bounds establish optimality
without relying solely on solver agreement. These bounds include the degree
bound and exact formulas where applicable; they are distinct from the final
solver \texttt{LB} column. A positive gap above a bound means that the bound
does not certify that witness as optimal. It neither refutes the bound nor
establishes a new result for an entire family. Sources, audit scope, and
per-run comparisons are stored in \path{results/analysis/general_pilot_v1/}.

The subsequent confirmation experiment retains the cohort and budget and
uses three repetitions per backend. Its analysis reports coverage by family
and $(h,k)$, separates the two ER densities, and compares runtimes on instances
solved to optimality in all three repetitions by both backends. Unsolved
instances remain in the cohort; repetitions are not counted as independent
graphs. Model size at a common label domain is analyzed separately below,
not inferred from runtime rankings.

\subsection{Model counts at a common label domain}
For each of the 117 pilot instances, choose $s$ as the smaller span of the
two validated witnesses. This is a feasible domain selected after the
experiment for size comparison, not a common initial bound used in the
historical runs. We rebuild order CNF without symmetry breaking or
simplification and compare actual variable/clause counts with the formulas.
Assignment ILP uses the same domain $0,\ldots,s$ and is counted from its
specification; backend presolve is not executed for this comparison.

Table~\ref{tab:common-model-size} describes representation size, not equivalent
solution difficulty. At the same $s$, both models have
$B=|E|F(s,h)+|D_2|F(s,k)$ forbidden-pair constraints. SAT adds
$|V|\max(s-1,0)$ monotonicity clauses; assignment adds $2|V|$ constraints.
SAT can therefore use fewer variables but more clauses than assignment uses
constraints. There is no requirement that every SAT count be smaller than
the corresponding ILP count. These counts do not replace historical counts
or constitute new runtime measurements.
